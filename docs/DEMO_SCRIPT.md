# Reset Agent — 4 分钟演示文稿

> 建议配合海报投屏，或打开 `https://reset-agent-green.vercel.app` 现场操作。

---

## 第 1 分钟：引发共鸣（0:00 → 1:00）

**【屏幕：海报左半部分 — 问题卡片 + 标语】**

> "各位，过去 20 小时里，有没有过这种时刻：
> 一个 bug 改了 3 小时还没好，明知道效率极低，但觉得'再试 10 分钟'。
> 最后凌晨 4 点才睡，早上 9 点继续懵。"

（停顿，环视）

> "这就是**无效硬扛**。它的恶性循环是——
> **越疲劳，越硬扛；越硬扛，越发散。**"

**【手指向海报左侧的问题卡片】**

> "番茄钟只会说'该休息了'，但它不回答'休息后做什么'。
> 冥想 App 让你深呼吸，但不解决'卡住的任务怎么办'。
> 健康工具劝你去睡觉，但黑客松里你不会去睡的。"

> "开发者真正需要的，不是'休息提醒'，而是**状态恢复 + 任务重启的一体化方案**。"

**【切屏或翻页】**

## 第 2 分钟：解决方案演示（1:00 → 2:00）

**【屏幕：海报右半部分 — 4步核心流程图】**

> "Reset Agent 是一个面向开发者的 **3 分钟 Reset 协议**。
> 它的核心就四步。"

**【指向流程图，逐条说】**

> "第一步，**识别状态**。你现在是卡住、疲劳、焦虑、困倦，还是身体报警？
> 不是让你选一个心情，而是让系统知道该用什么策略。"

> "第二步，**诊断卡点**。你把卡住的地方写一句话，LLM 会把它压缩成一个判断：
> 是任务边界太大？是信息过载？还是完美主义在作祟？"

**【切换到产品界面，或海报下方的 Mock 界面】**

> "第三步，**3 分钟倒计时 Reset**。
> 不是给你一个建议列表就完事，而是强制你走一个结构化流程：
> 第 1 分钟，身体恢复，离开屏幕；
> 第 2 分钟，把任务压缩成一个 5 分钟内可验证的小动作；
> 第 3 分钟，准备交接或重启。"

> "第四步，**交给 Agent**。当你硬扛冲动过高、清晰度过低、或者已经困倦时，
> Reset Agent 不会劝你'再坚持一下'——它会生成一段可直接复制给 Codex、Cursor、或 Claude Code 的 **Handoff Prompt**。"

**【展示 Prompt 示例，或指向海报上的 'Agent Handoff' 标签】**

## 第 3 分钟：差异化 & 技术亮点（2:00 → 3:00）

**【屏幕：海报整体，或切到 GitHub / 技术架构图】**

> "为什么是这个方案？市面上不是没有休息工具，但 Reset Agent 和它们有本质区别。"

> "第一，**不是被动提醒，是主动协议**。番茄钟到点就响，Reset Agent 是你**主动进入**的一个恢复工作流。"

> "第二，**任务上下文感知的诊断**。规则引擎会根据你输入的内容做启发式分析——
> 如果你写'调试 2 小时没定位'，它判断你疲劳时越改越乱，建议先恢复再定位；
> 如果你写'Demo 前发散'，它判断你需要收窄展示面，而不是加功能。"

> "第三，**LLM 增强 + 本地兜底的双模架构**。现场 Demo 最怕网络波动或 API 限流。
> Reset Agent 优先调用大模型生成个性化协议，一旦失败，零延迟 fallback 到本地规则引擎。
> 核心功能永远可运行，不依赖外部 API 的稳定性。"

> "第四，**Agent Handoff 不是附加功能，是核心设计**。它直接把'你睡觉，Agent 接管'这个口号落地成一个可执行动作。
> 交接 Prompt 包含【目标】【约束】【检查点】【交付】，Agent 接得住、做得完。"

**【可以补一句】**

> "技术栈很克制：Next.js + React + TypeScript，纯静态前端 + API 代理，部署在 Vercel。
> 24 小时里，我没选最炫的技术，选了最不容易出错的组合。"

> 生成一张'今日 Reset 卡片'——你今天 Reset 了几次，避免了多少分钟无效硬扛，清晰度和硬扛冲动的变化趋势。"

**【停顿】**

> "这个项目不是告诉你'去睡觉'，因为黑客松里你不会去睡的。
