## 二、问题定义：真实场景

### 场景1：无效硬扛
凌晨1点，一个bug改了3小时还没好。明知效率极低，但觉得"再试10分钟"。最后凌晨4点才睡，早上9点继续懵。

### 场景2：任务卡住
要写一个功能，但不知道从哪里开始。看了10篇文档，越查越乱，一上午过去了，代码一行没写。

### 场景3：疲劳累积
连续工作6小时，肩颈僵硬、注意力涣散、开始犯低级错误。但项目 deadline 在即，不敢休息。

**现有解决方案的缺陷**：
- 番茄钟：只提醒"该休息了"，不解决"休息后做什么"
- 冥想App：建议"深呼吸"，但不解决"卡住的任务怎么办"
- 健康工具：建议"去睡觉"，但黑客松里你不会去睡的

**核心洞察**：开发者需要的不是"休息提醒"，而是**"状态恢复 + 任务重启"的一体化方案**。

---

## 三、解决方案

Reset Agent 是一个面向开发者的轻量状态恢复工具。它不告诉你"去睡觉"，而是在你疲劳、卡住、焦虑时：

1. **识别状态**：你当前是疲劳/卡住/焦虑/困倦/肩颈痛？
2. **诊断原因**：AI分析你为什么卡住了（任务太大？信息过载？完美主义？）
3. **生成方案**：3分钟身体恢复 + 最小下一步行动
4. **倒计时引导**：按步骤执行，不是只给你建议
5. **恢复验证**：恢复前后状态对比，生成今日状态卡片
6. **Agent 接管**：当用户状态过差时，生成一段可以直接交给 Codex / Cursor / Claude Code 的任务交接 Prompt

**关键差异点**：
- 不是"休息工具"，而是"任务重启工具"
- 身体恢复和任务重启结合在一起
- 给出的是"最小下一步"，不是长篇建议
- 不是让 AI 陪你聊天，而是判断「继续 / 休息 / 交给 Agent」的下一步

## 四、核心功能（MVP）

### 功能1：状态诊断（1页）
- 5个emoji状态选择：🤯 卡住 / 😫 疲劳 / 😰 焦虑 / 😴 困倦 / 🤕 肩颈痛
- 文本输入："你现在卡在什么任务上？"
- 滑动条：1-10，"你现在有多想熬夜硬扛？"

### 功能2：AI Reset方案生成
- 调用大模型API生成个性化恢复方案
- 包含四个部分：
  - **身体恢复**：30秒呼吸 / 离开屏幕 / 肩颈拉伸
  - **任务诊断**：为什么卡住的分析
  - **最小下一步**：只做这一件事
  - **预计恢复时间**：3分钟 / 10分钟
  - **Agent Handoff Prompt**：当疲劳/困倦/硬扛评分过高时，生成可复制给 Codex / Cursor / Claude Code 的接管提示词

### 功能3：倒计时引导
- 按步骤执行恢复方案
- 第1分钟：身体恢复（离开屏幕）
- 第2分钟：任务简化（只看最小下一步）
- 第3分钟：开始执行

### 功能4：恢复前后对比 + 今日卡片
- 恢复前：状态分数记录
- 恢复后：重新打分
- 生成「今日黑客松状态卡片」（可截图分享）
- 累计统计：今日恢复次数、避免无效硬扛时间

### MVP增强点：Agent Handoff（不新增页面）

当用户的「疲劳、困倦、焦虑、想熬夜硬扛」评分过高时，Reset Agent 不只给休息建议，而是生成一段可复制的 Agent 接管 Prompt：

> 我现在要休息 20 分钟。请你接手这个任务，只做最小下一步：复现 bug，并列出 3 个可能原因，不要重构，不要扩展范围。

**为什么值得加**：
- 它直接呼应活动主题里的「你睡觉，Agent 接管」
- 它把项目从「AI 健康建议」升级成「开发者工作流工具」
- 它能在 Demo 时形成记忆点：Reset Agent 不只是提醒你停下，而是帮你把任务交接出去
- 它不需要新增复杂后端，只是生成结构化文本，开发成本很低

## 十三、全网搜索后的撞题风险与差异化策略

> 搜索时间：2026-05-21  
> 结论：**大方向会撞，精准形态不太会撞。**

### 1. 撞题风险判断

这次活动本身就把「开发者健康」「AI Agent」「睡觉时 Agent 接管」「可穿戴健康数据」放在了主题和奖项里，所以现场一定会有人做类似方向。

尤其是活动页里的 LAIFE Recovery Agent Challenge 明确提到：把 Oura / RingConn / Apple Watch / Garmin / WHOOP / Fitbit 等健康信号整合成决策信号，判断「何时继续、何时休息、何时让 Agent 接管」。

所以，如果 Reset Agent 只是做成「AI 提醒你休息一下」，会非常危险，很容易被评委归类成普通健康工具或番茄钟。

真正该抢的定位是：

> **开发者在无效硬扛发生时使用的 3 分钟恢复协议：判断继续、休息，还是把任务交给 Agent。**

| ADHD 微任务产品 | [Scramblie](https://apps.apple.com/us/app/scramblie/id6753355087) | AI micro-steps、3-20 分钟 timer、mood tracking | 它是移动端长期 productivity；Reset Agent 是黑客松/开发者现场重启 |
| 开发者 burnout 趋势 | [ITPro: AI amplifies burnout](https://www.itpro.com/software/development/ai-doesnt-solve-the-burnout-problem-if-anything-it-amplifies-it-ai-coding-tools-might-supercharge-software-development-but-working-at-machine-speed-has-a-big-impact-on-developers) | AI 工具提高速度，也放大验证、修复和发布压力 | Reset Agent 可以把「AI 时代开发者更累」作为问题背景 |

### 3. 最危险的误判

**不要把项目讲成：**
- AI 番茄钟
- AI 休息提醒
- AI 心理健康聊天机器人
- AI 任务拆分器
- 黑客松睡眠打卡工具

这些方向都有大量成熟产品或明显竞品，而且会让项目显得普通。

**要把项目讲成：**

> Reset Agent 是一个 Developer Reset Protocol。它在开发者进入疲劳、焦虑、卡住、无效硬扛状态时，快速判断下一步应该继续、休息，还是把任务交给 Agent，并给出一个 3 分钟可执行恢复流程。

### 4. 核心差异化升级：Agent Handoff

为了避免被看成「ChatGPT 包壳」，Reset Agent 应该在结果页加入一个很明确的模块：

**把任务交给 Agent**

示例输出：

```text
我现在要休息 20 分钟。请你接手这个任务。

当前任务：
修复登录页提交后没有跳转的问题。

当前状态：
我已经连续调试 2 小时，开始疲劳，容易乱改。

你的边界：
1. 只复现问题，不要重构。
2. 只检查登录表单提交、路由跳转、API 返回三处。
3. 输出 3 个可能原因和 1 个最小修复建议。
4. 不要改动无关文件。
```

这个模块的价值：
- 直接贴合活动口号：「Night · You go home and sleep. Your agent takes over」
- 让项目从健康建议变成开发工作流
- Demo 时更容易让评委记住
- 实现成本低，只需要生成结构化文本
- 可以自然连接 Codex / Cursor / Claude Code 等现场用户已经熟悉的工具

### 5. 答辩时可以直接说的话

> 市面上已经有很多番茄钟、休息提醒器和 AI 健康教练，但它们把「休息」「健康建议」和「任务管理」拆成了独立功能。
>
> Reset Agent 的差异点是：它面向开发者真实工作流，把「状态恢复」「任务重启」和「Agent 接管」合成一个 3 分钟协议。
>
> 当我已经疲劳、焦虑、卡住，甚至准备熬夜硬扛时，它不是泛泛地说“休息一下”，而是判断我该继续、该休息，还是该把任务交给 Agent，并给我一个最小可执行的下一步。

### 6. 最终判断

**会撞主题，但不必怕。**

真正要怕的是把项目做得太泛、太温吞、太像普通 AI 问答。只要把产品收束成：

> **Developer Reset Protocol + Agent Handoff**

它就能和番茄钟、休息提醒器、AI 健康教练、团队 burnout 仪表盘拉开距离。
